# /preflight

デッキが正しくビルド、デプロイ、発表できることを確認します。これは**技術**チェックです。内容の質は`/review`の役割です。オプション：$ARGUMENTS

## 1. チェックを実行する

1. `node_modules`が存在すること（なければ`pnpm install`）。
2. **`pnpm check`**（依頼された場合、またはネットワークがない場合は`--offline`を付ける）。これは人間が実行するのと同じコマンドです。すべての`slides*.md`デッキをビルドし（ビルドの失敗は最初に報告すべき事項で、関連するエラー行を添えます）、その後`pnpm preflight`を実行します。これは以下を報告します：
   - 対応する`routeAlias`がない`<Link to>`のターゲット、および数値のリンク（warning）
   - デプロイ時のbase pathの下で壊れる、ルート絶対の`href="/…"` / `src="/…"`と`/public/…`のパス
   - インストールされていないアイコンセットのアイコン、および存在しないアイコン名（何も表示されません）
   - HTMLの行の中にあるMarkdown（バッククォート、`**`）。そのまま文字として表示されます
   - 日本語テキスト中のem-dashと半角スペース
   - デッキの構成：セクション番号が順番どおりであること、アジェンダと振り返りがすべてのセクションを網羅していること、締めのスライドがあること
   - 翻訳の対応関係：スライド数、`routeAlias`、レイアウト、セクション番号、スライドごとのクリック数。存在しない、または翻訳元より古い対になるページ。日本語以外のデッキにある全角の句読点
   - `as-of`のない、または6か月より古い`<BrowserSupport>`
   - シークレット、社内アドレス、社内サブドメイン（デッキは公開されます）
   - 骨組みに残っている`TODO`、リポジトリ名と`package.json`のname、`package-lock.json`
   - ソフトリミット（info）：15行を超えるコードブロック、箇条書きの多いスライド
   - 404になる外部リンクと`<MdnLink>`のターゲット（デッキのMDNロケールで確認）
3. **Slidev MCP**（`pnpm dev`が動いている場合）：`slidev-list-slides`がスクリプトと同じスライド数を報告するはずです。異なる場合は、まず古いdev serverを疑ってください（ファイルが存在する前にimportが追加された）：`slides.md`をもう一度保存して比較します。それでも異なる場合にだけ、スクリプトを疑ってください。
4. **デプロイのパス：**`pnpm preview`は`dist/`を実際のサブパスで配信します。バックグラウンドで起動し、デッキのURLと`public/`の下の各ファイルを`http://localhost:4173/<repo>/…`で`curl`し、停止します。200以外はすべてbase pathのバグです。
5. **最後のデプロイ**（`gh`が使えて、リポジトリにremoteがある場合）：Pagesのworkflowについて`gh run list --workflow deploy.yml --limit 1`。失敗した、または存在しないrunを報告してください。ビルドはしたがデプロイをスキップしたrunは、Pagesがまだ有効になっていないことを意味します：`pnpm pages`を提案してください（GitHubリポジトリの設定を変更するので、先に確認してください）。

## 2. 報告する

重大度ごとにまとめ、簡潔にします：

- **ブロッカー：**ビルドの失敗とスクリプトのエラー。デプロイされたデッキやトークを壊します。
- **修正すべき：**このデッキにとって実際に問題となるwarning（例：数値のリンク、古いサポート状況のデータ、半角スペース）。
- **判断が必要：**意図的かもしれないwarning（公開されている社内サブドメイン、botをブロックするリンク、発表者が残したい`TODO`）。それぞれ、なぜ問題ない可能性があるのかを説明してください。

それぞれに`file:line`と修正方法を添えてください。スクリプトの出力全体を貼り付けないでください。

## 3. 修正する

機械的なものは修正を提案してください：不足している`@iconify-json/<set>`のインストール、em-dashの置き換え、`routeAlias`を追加して`<Link>`をそれに切り替える、`BASE_URL`のパス、残骸の削除。発表者が同意した後にだけ適用し、その後`pnpm preflight`とビルドを再実行してください。

チェック自体が間違っている場合（誤検知、または`scripts/preflight.mjs`のバグ）は、まず発表者に修正内容を提案し、了承を得てからスクリプトを修正して発表者に伝えてください：テンプレートのメンテナーに報告する価値のある、テンプレートレベルの修正です。

## 4. 発表当日のチェックリスト

`pnpm check`は`docs/checklists.md`から「発表当日」のチェックリストを出力します。最後に発表者と一緒にそれを確認し、あなたが確認できた項目にチェックを付けてください。
