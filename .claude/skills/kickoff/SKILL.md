# /kickoff

このテンプレートを具体的なトークに仕立てます。成果物は、`CLAUDE.local.md`に記録された合意済みのスコープと、それを反映して埋めた骨組みのデッキで、そのまま`/slide`に進める状態にします。**ここでは内容のスライドは書きません**。これは[docs/talk-plan.md](../../../docs/talk-plan.md)をAIと進めるルートで、加えて`TODO`を埋めます。質問の中身はtalk-plan.md側にあり、ここでは複製しません。

発表者からのメモ（あれば）：$ARGUMENTS

`PRINCIPLES.md`、`HANDBOOK.md`、`docs/talk-plan.md`がまだコンテキストにない場合は、先に読んでください。会話は発表者が使う言語で進めてください（デフォルトは日本語）。会話形式で作業します：短いやり取りで、一度に一つの話題だけを扱います。選択肢がはっきりしている場合は選択式の質問にし、自由回答の余地も残してください。

## 0. 現状を確認する

- `CLAUDE.local.md`がすでにある場合、トークのスコープは決定済みです。そのピッチと構成を見せ、**更新**するか**最初からやり直す**かを尋ねてください。黙って上書きすることは絶対にしません。
- `slides.md`がもう`TODO`の骨組みでない（`title:`に`TODO`がない）場合、デッキには内容があります。手順4では、何が変わるのかを正確に示して明示的な確認を得るまで、何も削除・上書きしないでください。
- ガイド（`guide.md`、`guide/`、`public/guide/`）はテンプレートの一部です。手を加えないでください。

## 1. トークを理解する

`docs/talk-plan.md`の「最初に答える質問」のうち、**テーマと要点**、**なぜ今か**、**言語**を、発表者がすでに話した内容に合わせて尋ねてください。要点は機能の羅列ではなく、具体的な一つに絞るよう促します。言語では次を記録します：

- メインデッキの言語（`slides.md`の`htmlAttrs.lang`。デフォルトは日本語）
- 第二言語デッキ：なし、またはどの言語か
- 執筆言語（メインと異なる場合。例：「英語で書いて、`/translate`で日本語に翻訳する」）

加えて、AIと作るときだけの質問：

- **進め方**：AIにどう作業してほしいか（スライドごとにレビュー、セクションごと、デッキ全体を書いてからレビュー、その他）。発表者の言葉どおりに記録します。
- 任意：表紙に発表者名・日付を入れるか（デフォルト：入れない）。

## 2. トークの形を決める

残りの質問（**導入**、**セクション**、**まとめ**、**収まるか**、**却下したアイデア**）について具体案を出し、発表者が**明示的に承認する**まで繰り返してください。加えて、一行の**ピッチ**（誰向けで、何が得られるか）を提案します。

- セクションごとの時間配分は押し付けないでください。ペース配分は発表者が決めることです。
- 繰り返しの中で、**却下したアイデアと切り口はすべて**、一行の理由とともに記録してください。
- 原則（`PRINCIPLES.md`）が損なわれそうな場合は反対意見を述べてください：50分には広すぎる、明確な要点がない、ほとんど読むだけのセクションがある、デモのためのデモになっている、など。

## 3. リポジトリを確認する

- `git config --get remote.origin.url`からリポジトリ名を読み取ってください（`pnpm preflight`もこれを確認します）。`febi-<topic>-<発表日YY.MM.DD>`（日付はリポジトリの作成日ではなく発表日）に一致しない場合は、名前を**提案**してください。発表日が分からなければ、提案する前に尋ねてください。自分では何もリネームしません：リネームはGitHub上で発表者が判断することです。リネーム後は、導出されるbase pathが正しく保たれるよう、`git remote set-url origin <new-url>`を実行してもらう必要があります。
- `package.json`の`"name"`をリポジトリ名に設定してください。
- Pagesがまだ設定されていなければ、`pnpm pages`の実行を提案してください（GitHub CLIでPagesを有効化し、最初のデプロイを開始します。発表者のGitHubリポジトリに対する操作なので、先に確認を取ってください）。`gh`がない場合：Settings → Pages → Source：**GitHub Actions**、次にActions → Run workflow。

## 4. 骨組みを埋める

テンプレートの`slides.md`には、仮のセクションが3つ（`pages/01-part-1.md` … `03-part-3.md`）と、あちこちに`TODO`があります。パターンは[docs/recipes.md](../../../docs/recipes.md)（「デッキの構成」）にあります。何が変わるかを説明し、了承を得てください。その後、**この順番で**進めてください（起動中の`pnpm dev`は、ファイルがすでに存在する`src:`インポートしか読み込みません）：

1. **`pages/`**：合意したセクションごとに`pages/0N-<alias>.md`を一つずつ作り、中身はセクション区切りだけにします。それぞれに`routeAlias`と固有のアクセント色を設定します：順に、なし（purple）、`var(--green)`、`var(--cyan)`、`var(--orange)`、`var(--pink)`。
2. **`slides.md`**（デッキファイルの中で最後）：タイトル、表紙の絵文字とサブタイトル、`htmlAttrs.lang`、セクションごとにアジェンダ項目を一つと`src:`インポートを一つ、振り返り（セクションごとに要点を一つ。今はセクションのaliasにリンク）、締めのスライドの見出しと行動の呼びかけを埋めてください。まとめのスライドは`TODO`のまま残します（全セクションを書いた後に`/slide`が書きます）。リソースのリンクは、自分で開いて確認した（200が返り、正しいページである）ものだけを追加し、そうでなければ`TODO`のまま`/slide`に任せてください。HTMLの行の中ではMarkdownは解釈されません：`<code>`を使ってください。
3. もうインポートされていない**仮のページ（`pages/0N-part-N.md`）を削除**してください。
4. **言語**（HANDBOOK.mdの「第二言語デッキ」）：
   - **第二言語デッキ**はここでは作りません。メインの言語で書き進めてから`/translate`で作ります（中身のない対になるファイルを先に作ると、ずれの元になるため）。どの言語のデッキを作る予定かを`CLAUDE.local.md`の「言語」に記録します。
   - **執筆言語がメインと違う場合**（例：英語で書いて、日本語のメインデッキにする）：骨組みは`slides.<執筆言語>.md`と`pages/0N-<alias>.<執筆言語>.md`に作り（`htmlAttrs.lang`はその言語）、`slides.md`は`TODO`のまま残します。日本語の`slides.md`は後で`/translate`で作ります。
   - **メインデッキ自体が日本語でない場合**（日本語版を作らない）：`slides.md`の`htmlAttrs.lang`をその言語にします。`utils/i18n.ts`は日本語以外のデッキに英語のUIテキストを返すので、必要なら拡張します。
5. それ以外（コンポーネント、スタイル、ドキュメント、ガイド、設定）はそのままにしてください。

## 5. `CLAUDE.local.md`を書く

[docs/talk-plan.md](../../../docs/talk-plan.md)のテンプレートから作成し、合意したことをすべて記入します：ピッチ、聴衆と要点、言語の設定、進め方、構成（aliasとアクセント色を含む）、却下したアイデア、未決事項、スライドの進捗（すべてのセクションを「未着手」に）。

## 6. 確認して引き継ぐ

- `pnpm check --offline`が通ること（すべてのデッキをビルドし、preflightを実行します）。まとめのスライドと締めのリソースの`TODO`警告は想定どおりで、それ以外の`TODO`は想定外です。
- `pnpm dev`が起動している場合は、`slidev-list-slides`（Slidev MCP）で、デッキに表紙、アジェンダ、セクションごとのセクション区切り、振り返り、締めのスライドがあること、そしてすべての`<Link to>`のaliasが存在することを確認してください。
- 作成・削除したものを簡潔に報告し、次のステップを提案してください：最初のセクションの`/slide`（記録した進め方に従って）。
