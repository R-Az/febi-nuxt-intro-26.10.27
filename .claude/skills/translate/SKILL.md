# /translate

このデッキを**<target language>を話す聴衆**向けに調整します。依頼：$ARGUMENTS

これは一文ずつの翻訳ではありません。ルール（同一に保つもの、聴衆に合わせて調整するもの、言語ごとの注意点）はすべて`HANDBOOK.md`の「第二言語デッキ」にあり、手作業で翻訳する人と同じ内容です。ここでは、その進め方だけを定めます。

## 0. 準備

- `CLAUDE.local.md`を読みます：言語の設定（メインデッキ、第二言語デッキ、下書きの言語）、スライドの進捗（「翻訳待ち（translation pending）」の印）、そして**用語表**（あれば）。
- **翻訳元 → 翻訳先**を決めます。通常は下書きのデッキ → もう一方のデッキです（例：`slides.md` →
  `slides.en.md`、または英語の下書き → 日本語のメインデッキ）。依頼内容や設定があいまいな場合は質問してください。
- **範囲：**`sync`（デフォルト）は、「翻訳待ち」の印が付いたスライド、または翻訳先が最後に更新されてから翻訳元が変更されたスライドだけを対象にします（翻訳元ファイルの`git diff` / `git log`で確認）。`all`またはセクションのエイリアスを指定した場合は、まさにその範囲を対象にします。
- 翻訳先のデッキがまだ存在しない場合は、同じ形で作成します（実行中のdev serverがimportを拾えるよう、ページファイルを先に、エントリーファイルを最後に）：`slides.<lang>.md` + `pages/0N-<alias>.<lang>.md`、headmatterに`htmlAttrs.lang: <lang>`（HANDBOOK.mdの「第二言語デッキ」）。`package.json`のscriptsは不要です：`pnpm dev slides.<lang>.md`、`pnpm export slides.<lang>.md`。

## 1. ルール

`HANDBOOK.md`の「第二言語デッキ」の「同一に保つもの」「翻訳ではなく、聴衆に合わせて調整する」と、翻訳先の言語の注意点（「日本語のテキスト」「英語のテキスト」「その他の言語」）をすべて適用します。加えて：

- 構成を変える必要がある場合は、変える前に発表者に質問し、合意した差分を`CLAUDE.local.md`に記録します。
- 用語の表記がよく使われるもので2通りある場合は、発表者に質問し、`CLAUDE.local.md`の**用語表**に記録します。

## 2. 作業を進める

ペースは`CLAUDE.local.md`の進め方（スライドごと、セクションごと、…）に従います。スライドごとに：

1. 翻訳元のスライドとそのノートを読みます。そのスライドの1つのポイントと、文化に依存する部分を特定します。
2. 上のルールを適用して、翻訳先のスライドを書きます。
3. 翻訳元のスライド自体に問題がある場合（不明瞭、誤り、長すぎる）は、片方の言語だけで黙って直さないでください：問題を指摘し、発表者が同意したら両方のデッキを直します。

## 3. 確認と報告

- **対応関係：**スライド数が同じこと、タイトルが対応していること、`routeAlias`と`<Link to>`のターゲットが同じこと。ファイル同士を比較し、`pnpm preflight`の対応関係のチェックで確かめます（Slidev MCPは`pnpm dev`のポート3030のデッキしか見えないため、第二言語デッキは`pnpm dev slides.<lang>.md --port 3031`で目視確認を依頼します）。
- `pnpm check --offline`が通ること（対になるファイルを含め、すべてのデッキをビルドし、対応関係と日本語の表記もチェックします）。
- `CLAUDE.local.md`のスライドの進捗（翻訳済み）と用語表を更新します。
- 差分ではなく、**調整のメモ**を報告します：言い回し以外にローカライズしたもの（例、データ、参考資料、削除した言葉遊び）、選んだ用語、そして見た目で確認すべき点（翻訳先の言語ではみ出しそうなスライド）。
