# /demo

このトークのインタラクティブなデモを作ります。依頼：$ARGUMENTS

`CLAUDE.local.md`（構成、「見せ方」の列、却下したアイデア）と、デモを置くスライドを読んでください。

デモのルールはすべて`HANDBOOK.md`の「デモ」にあります（手作業でデモを作る人と同じ内容です）。ここでは、その進め方だけを定めます。

## 1. そもそもコンポーネントにすべきか？

`HANDBOOK.md`の「まず、そもそもコンポーネントにすべきか」の順に確認し、最初に当てはまったところで止まってください。答えが「コンポーネントは不要」なら、そう伝えて代案を示し、発表者が強く望まない限りそこで止まってください。

## 2. コードを書く前に設計する

`HANDBOOK.md`の「小さく設計する」の各点（見せること、操作、サイズ、違いを測る方法、ネットワーク）について、発表者と数行で合意してください。

## 3. 実装する

`HANDBOOK.md`の「作る」に従い、「過去のデッキで見つかった落とし穴」のうち当てはまるものはすべて対処してください。このトークのコンポーネントは`components/`直下に作ります。`components/common/`（全トーク共通）と`components/guide/`（ガイド用）は変更しません。

## 4. スライドに配置する

`HANDBOOK.md`の「スライドに置く」に従います。

## 5. 確認して引き継ぐ

- `pnpm check --offline`が通ること（すべてのデッキをビルドしてコンポーネントをコンパイルし、preflightを実行します）。
- 頼まれない限り、自分でブラウザを操作しないでください。発表者に確認すべき点を伝えます：
  - スライドが表示されるとデモが始まり、離れると止まる
  - 操作部分をクリックした後も矢印キーでスライドを移動できる
  - カラムに収まっている
  - 言語のデッキが二つある場合は、その両方で
  - パフォーマンスデモでは、発表者のマシンで違いが見える
- `CLAUDE.local.md`のそのスライドの進捗を更新してください（デモ完成 / 要確認）。
