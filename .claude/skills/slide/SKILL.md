# /slide

このトークのスライド内容を書きます。依頼：$ARGUMENTS（空の場合は「構成の次のスライド」）。

## 書く前に

1. **トークの文脈**：`CLAUDE.local.md`を読んでください。存在しない場合は、作業を止めて`/kickoff`を提案してください。そこから次を把握します：ピッチ、構成（セクション、alias、要点、「見せ方」）、却下したアイデア、言語の設定、**進め方**、スライドの進捗。
2. **現在地**：`pnpm dev`が起動していればSlidev MCPを使います。存在するスライドは`slidev-list-slides`で、依頼が「このスライド」と言っている場合は現在表示中のスライドを`slidev-get-info`で確認します。起動していなければ`slides.md`と`pages/`を読んでください。
3. **何を書くか**：「next」（次）は、構成の中で最初の未完成のスライドです。セクションのaliasなら、そのセクションです。スライド番号や「このスライド」なら、そのスライドの修正です。
4. **どれだけ書くか**：進め方に厳密に従ってください。「スライドごと」なら**一枚書いたら止まり**、レビューを待ちます。進め方が記録されていなければ、一枚書いて確認してください。

## スライドを書く

まず一文で決めてください：**このスライドのただ一つのポイントは何か**。ポイントが二つあるなら、スライドは二枚です。

次に[docs/recipes.md](../../../docs/recipes.md)の型（ソース付きの表示は`pnpm guide`）をもとに組み立てます。ルールは複製せず、次の原典に従ってください：

- `PRINCIPLES.md`のすべての原則（語るより見せる、単体で伝わる、簡潔に、でも漏れなく、コード、クリック、読みやすさ、出典、公開）
- `HANDBOOK.md`の「スライドを書く」（1スライド1ポイント、収まり、デモの横のコード、セクションの終わり）、「スタイル」「アイコン」「リンク、アセット、出典」、そして「第二言語デッキ」の「日本語のテキスト」

AIとして特に守ること：

- **デモが必要なら**、コンポーネントを配置した状態でスライドを書き、コンポーネント本体は`/demo`に任せます（その旨を伝えます）。
- **事実は記憶で書かず、調べてください**（MDN、仕様、web.dev）。引用する前にページを開き、その具体的な主張が書かれていることを確認します。
- 書き終えたら、`docs/checklists.md`の「内容のレビュー」の「ジュニアテスト」と「原則」の項目で自己確認します。

## 言語

`CLAUDE.local.md`に記録された**執筆言語**（通常はメインデッキの言語）で書いてください。第二言語デッキがある場合は、書きながら翻訳しないでください：スライドの進捗でそのスライドを「翻訳待ち」とし、`/translate`に任せます。

## セクションの終わりとトークの終わり

- セクションのスライドを書き終えたら、その**要点**に`routeAlias`付きのスライドがあることを確認し、振り返りの項目のリンク先をセクション区切りからそのaliasに変えてください。
- 最後のセクションが終わったら：**振り返り**を完成させ（セクションごとに要点を一つ）、その後ろ、締めの前の**まとめ**スライドを書き（チートシート、判断表、または3〜5個のポイント。短いトークなら振り返りと1枚にしてもよい）、**締めのスライド**のリソースを埋めてください（参考文献一覧ではなく、見に行く価値のあるものを少数）。

## 書いた後

1. `pnpm preflight`を実行し（外部リンクもすべて確認します。`--offline`はネットワークがない場合にだけ付けてください）、新しいスライドについて報告された問題を修正してください。devサーバーが起動していれば、`slidev-list-slides`でスライドが想定した位置にあることを確認してください（編集後は番号がずれます。推測せず、もう一度一覧を取得してください）。セクションファイルを追加するときは、`src:`インポートを追加する前にファイルを作成してください。それでもスライド一覧が古いままに見える場合は、`slides.md`をもう一度保存してください。
2. `CLAUDE.local.md`の**スライドの進捗**を更新してください（下書き済み / 翻訳待ち / デモ待ち）。
3. 簡潔に報告してください：どのスライドか、どのファイルか、ブラウザで何を見るべきか（はみ出しそうな箇所、順に進めるクリック）。スライドの内容は貼り返さないでください。
4. 進め方がそう指定していれば、ここで止まってください。コンポーネントが未完成なら`/demo`を、セクションやデッキが完成したら`/review`を提案してください。

## 修正

スライドの作り直しを頼まれたら、頼まれた部分だけを変え、aliasとリンクはそのまま保ち、何を変えたかを伝えてください。依頼が`PRINCIPLES.md`と矛盾する場合（例：「この4段落を追加して」）は、原則に一度だけ触れ、代案（図、デモ、スライドの分割）を示したうえで、発表者の判断に従ってください。
