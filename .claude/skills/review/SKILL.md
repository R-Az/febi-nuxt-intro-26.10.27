# デッキのレビュー

このリポジトリのFEBiトークをレビューしてください。範囲：$ARGUMENTS（空または`all`＝デッキ全体）。

**背景。**FEBi（Frontend Biweekly）はSun Asteriskの社内フロントエンドトークシリーズです。トークはSlidevのデッキで、60分の枠（トークは最大50分、その後Q&A）でライブで発表され、その後GitHub Pagesで公開されて、発表者なしで読まれます。聴衆は日本とベトナムのジュニアからシニアまでのフロントエンド開発者で、大半が日本語話者です。メインデッキは通常日本語です。

**独立性。**あなたはこのデッキがどのように作られたかを見ていませんし、見るべきでもありません。読むのは以下だけです：

1. `PRINCIPLES.md`と、`docs/checklists.md`の**内容のレビュー**チェックリスト：レビューの基準です。
2. `CLAUDE.local.md`のうち、**ピッチ**、**聴衆と要点**、**言語**、**構成**のセクションだけ（見出しが日本語化される前に作られたデッキでは、英語名のPitch、Audience and takeaway、Language、Outline）：トークの意図です。それ以外（下書きのメモ、却下したアイデア、進捗）は無視してください。ファイルが存在しない場合は、デッキから意図を推測し、そのことを明記してください。
3. デッキ：メインのエントリー（`slides.md`）と、それが`src:`でimportしている`pages/`のファイル、さらにデモが何を見せるのかを理解するため、スライドが使っている`components/*.vue`。Slidev MCPのツールが使える場合（dev serverが動いている場合）は、`slidev-list-slides`で**表示上のスライド番号**を取得し、その番号でスライドを参照してください。そうでなければファイルから数え、そのことを明記してください。
4. 第二言語デッキ（`slides.<lang>.md`）。下の調整のチェックのためだけに読みます。

## 確認すること

`docs/checklists.md`の**内容のレビュー**のすべての項目（人間のレビュアーと同じリスト）を、スライドごとに、その後トーク全体で確認してください。チェックリストに加えて：

- **事実確認が最も重要です**：スライド上の事実に関する主張をすべて列挙し、それぞれをチェックリストにある一次情報で**独立して**確認してください。スライド自身の出典を鵜呑みにせず、開いて、主張どおりのことが書かれているかを確かめます。
- **長さ**：デモとクリックのステップも含めて50分に収まるかを見積もり、明らかに長すぎる、または短すぎる場合は指摘してください。
- **言語**：不自然な日本語には書き直し案を示してください。第二言語デッキは、いくつかのスライドを抜き出して確認するだけにし、全体はレビューしないでください。

## 出力

発表者向けのレポートは、前置きも含めて最初から日本語で書いてください（「レビューします」などの英語の前置きは不要です）。ただし、上の範囲の引数が別の言語で書かれている場合は、その言語を使ってください。スライドの文章は元の言語のまま引用してください。

1. **結論：**トークが成立しているか、そして最大のリスクは何かを2〜3文で。
2. **指摘**、影響の大きい順（高 / 中 / 低）。それぞれについて：スライド番号とタイトル、`file:line`、何が問題か、この聴衆にとってなぜ重要か、そして**具体的な修正案**（書き直し、分割、図のアイデア、削除）。
3. **事実確認の表：**主張（短く）、スライド、判定（✅ 確認済み / ❌ 誤り / ⚠️ 古いまたは不正確 / ❓ 確認不可）、情報源のURL。❌と⚠️はすべて指摘にも含めてください。
4. **聴衆から出そうな質問：**ジュニアやシニアが聞きそうな質問を5〜8個。それぞれ、どのスライドから出る質問か、デッキがすでに答えているかを添えてください。

最後に、このレビューでは何も変更していないことを伝えてください。何を反映するかは発表者が決めます。
