# 検証の実行手順

検証は2段に分けて、計8回やります。1段目でアプリをゼロから作らせ、2段目でそのアプリに機能を足させます。毎回、リポジトリの外にある空のフォルダで新しいClaude Codeのセッションを起動し、指示文を貼って作らせます。終わったら、このリポジトリで別のセッションを開いて、計測・判定・記録を任せます。

| 順番 | 回 | 作業フォルダ | 指示文の1行目 |
| --- | --- | --- | --- |
| 1 | `nuxt-1` | `~/dev/inhouse/febi-nuxt-experiment/nuxt-1/` | `Nuxt` |
| 2 | `next-1` | `~/dev/inhouse/febi-nuxt-experiment/next-1/` | `Next.js（App Router）` |
| 3 | `nuxt-2` | `~/dev/inhouse/febi-nuxt-experiment/nuxt-2/` | `Nuxt` |
| 4 | `next-2` | `~/dev/inhouse/febi-nuxt-experiment/next-2/` | `Next.js（App Router）` |

作業フォルダをこのリポジトリの外に置いているのは、Claude Codeが起動したフォルダの親にある`CLAUDE.md`も読み込むためです。`experiment/`の中で起動すると、このリポジトリの指示がAIに混ざります。

## 1回の流れ

### 1. 起動する

Claude Desktopで新しいセッションを作り、フォルダに作業フォルダ（例：`~/dev/inhouse/febi-nuxt-experiment/nuxt-1`）を選びます。

- MCPサーバーやコネクタが有効になっていれば、そのセッションではオフにする
- モデルとeffortは、4回とも同じにする（1回目に選んだものを `results/experiment/conditions.md` に控える）

### 2. 指示文を貼る

[prompt.md](prompt.md) のコードブロックの中身をコピーし、1行目の `{FRAMEWORK}` を上の表の値に置き換えて、1回だけ貼ります。

### 3. 見守る

途中でコードを読んで口を出したり、ヒントを出したりはしません。AIが止まったときだけ、次の決まった文面を返します。

| 状況 | 返す文面 |
| --- | --- |
| エラーが残ったまま完了報告をした | エラーが残っています。受け入れ条件をすべて満たすまで続けてください。 |
| 受け入れ条件を満たしていないのに完了報告をした | 受け入れ条件 N が満たされていません。続けてください。（Nは番号だけ） |
| 確認や許可を求めて止まった | 合理的に判断して進めてください。 |
| 同じエラーで3回続けて失敗し、進まなくなった | そこで打ち切る |

コマンドの実行許可を求められたら許可します。これは介入に数えません。

「受け入れ条件を満たしていない」と判断するのは、完了報告に ✗ や △ があるときです。自分でアプリを動かして確かめるのは、後の判定セッションに任せます。

### 4. 終える

AIが完了報告を出し、返す文面がなくなったら `/exit` で終了します。開発サーバーが動いたままなら止めます。

時刻、介入の回数、完了報告は、判定セッションがセッションのログから読み取るので、メモは要りません。打ち切った場合や、気になったことがあった場合だけ一言メモしておきます。

### 5. 計測・判定を任せる

このリポジトリ（`febi-nuxt-intro-26.10.27/`）で新しいClaude Codeのセッションを開き、[judge-prompt.md](judge-prompt.md) の指示文を、回の名前（`nuxt-1` など）を入れて貼ります。

判定の中には、人の目で確かめる項目があります（CSVをExcelで開いたときに文字化けしないかなど）。判定セッションから選択式で聞かれるので、答えてください。

## 2段目：機能を足す

1段目のその回の判定が済んだら、そのアプリに機能を足させます。順番は `nuxt-1-add` → `next-1-add` → `nuxt-2-add` → `next-2-add` です。

### 1. 作業フォルダを用意する

1段目のアプリをコピーし、始める前の状態をコミットしておきます（後で差分を測るため）。`nuxt-1` の部分は回ごとに変えます。

```bash
cd ~/dev/inhouse/febi-nuxt-experiment && rsync -a --exclude .git nuxt-1/ nuxt-1-add/ && cd nuxt-1-add && git init -q && git add -A && git commit -qm base
```

`nuxt-1-add` と `next-1-add` は用意してあります。

### 2. 指示文を貼る

1段目と同じように、新しいセッションをその作業フォルダで作ります。[prompt-add.md](prompt-add.md) の指示文を、そのまま1回だけ貼ります（フレームワーク名の置き換えはありません）。

### 3. 見守る・終える

1段目と同じです。決まった文面だけを返します。

### 4. 計測・判定を任せる

このリポジトリで新しいセッションを作り、回の名前を `nuxt-1-add` のようにして判定を頼みます。

```text
検証の nuxt-1-add が終わりました。experiment/judge-prompt.md の指示どおりに、計測・判定・記録をしてください。
```

## 守ること

- **順番どおりに実行する**：Nuxt → Next.js → Nuxt → Next.jsの交互です。途中でAIのバージョンが上がっても、片方だけが影響を受けないようにするためです。
- **作業フォルダでは、この検証以外の作業をしない**：別の会話の内容が混ざらないように、毎回新しいセッションで始めます。
- **4回の間でClaude Codeを更新しない**：自動更新で上がった場合は、判定セッションに伝えて `conditions.md` に記録してもらいます。
- **全部のセッションに同じ条件がかかるもの**（ユーザー設定のスキルなど）は、そのままで構いません。4回とも同じ条件になるからです。
