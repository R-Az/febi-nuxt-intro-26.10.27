# 計測・判定セッションへの指示文

検証の1回が終わるたびに、このリポジトリで新しいClaude Codeのセッションを開き、下のコードブロックの中身を貼ります。1行目の `{RUN}` を回の名前（1段目は `nuxt-1`、`next-1`、`nuxt-2`、`next-2`、2段目は `nuxt-1-add` など）に置き換えます。打ち切った場合や、気になったことがあった場合は、最後の行に書き足します。

```text
検証の {RUN} が終わったので、計測・判定・記録をしてください。

# 対象
- 作られたアプリ：~/dev/inhouse/febi-nuxt-experiment/{RUN}/
- セッションのログ：~/.claude/projects/ の中で、作業フォルダのパスに対応するフォルダ（例：-Users-ryoga-azuma-dev-inhouse-febi-nuxt-experiment-{RUN}）にある .jsonl

# 最初に読むもの
- experiment/README.md（計測のしかた、受け入れ条件の判定、記録の形式）
- experiment/prompt.md（AIに渡した指示文と受け入れ条件）
- {RUN} が「-add」で終わる2段目なら、experiment/prompt-add.md も読む。README の「2段目で追加で測るもの」と「2段目の判定」に従い、`git diff` で変更量を測り、A1〜A6と条件1〜12を判定する
- results/experiment/conditions.md（あれば。固定条件の記録）

# やること
1. 固定条件を確かめる。ログから Claude Code のバージョンとモデルを読み取り、results/experiment/conditions.md と比べる。ファイルがなければ作って記録する。前の回と違っていたら、作業を止めて私に知らせる。
2. ログから次を読み取る。
   - 開始時刻（最初のユーザーメッセージ）と終了時刻（最後のAIの応答）、所要時間（分）
   - ターン数（私が送ったメッセージの数。最初の指示文を含む）
   - 介入の回数と、それぞれの時刻・送った文面（最初の指示文以外のメッセージ。コマンドの実行許可は数えない）
   - ビルドと型チェックが失敗した回数
   - 最後の完了報告の全文
3. トークン数とコストを `npx ccusage@latest session --json` で取り、このセッションの値を使う。どのセッションか分からなければ、ログのセッションIDで突き合わせる。
4. コード量と依存を測る。
   - `npx cloc --exclude-dir=node_modules,.nuxt,.next,.output,dist .` の合計行数
   - import の行数（README の「計測のしかた」のコマンド）
   - package.json の依存のうち、プロジェクト作成コマンドが入れたもの以外。どれが作成コマンドのものか確信が持てなければ、その旨を notes に書く
5. 受け入れ条件1〜12を、README の「受け入れ条件の判定」の手順で判定する。AIの完了報告は参考にとどめ、自分で動かした結果で付ける。
   - 自分で確かめられるもの：型チェック・テスト・ビルドの実行、開発サーバーの起動、APIの 401 / 403（curl）、CSVの中身（BOM、列の順番、日付と時刻の書式、打刻漏れの行）、計算ルール（初期データの数件を手で計算して照合）、定期処理の設定、README の手順
   - 画面の操作は、使えればアプリ内のブラウザで確かめる
   - CSVをExcelで開いたときの文字化けなど、人の目が要るものは、選択式の質問で私に聞く
6. 記録を書く。
   - results/experiment/{RUN}.json（README の「記録の形式」どおり）
   - results/experiment/{RUN}-report.md（AIの完了報告の全文）
7. 作られたアプリをこのリポジトリにコピーする。コピー先は experiment/nuxt/run-N/ または experiment/next/run-N/（2段目は run-N-add/）。node_modules、.nuxt、.next、.output、dist、.git は除く。

# 守ること
- 作られたアプリのコードは直さない。判定のために動かすだけにする。不具合を見つけても修正せず、記録に書く。
- 数値は、ログ・ccusage・コマンドの出力からだけ写す。推測で埋めない。取れなかった値は null にして、理由を notes に書く。
- 開発サーバーなど、自分で起動したものは最後に止める。
- コミットと push はしない。
- 報告と質問は日本語で、質問は選択式にする。
- 最後に、記録した主な数値と、条件ごとの判定（○／△／✗）を表で報告する。
```
