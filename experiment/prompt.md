| 実行 | `{FRAMEWORK}` |

| Next.js | `Next.js（App Router）` |

指示文には、フレームワーク固有の用語（`server/api`、`route.ts`、`useFetch` など）や、特定のライブラリ名を入れていません。どちらかに有利にならないようにするためです。

```text
{FRAMEWORK}（最新の安定版）で、小さな会社向けの勤怠管理Webアプリを作ってください。

# 進め方のルール
- TypeScriptで書く。
- 公式・定番のモジュールやライブラリは自由に使ってよい。追加したものは、完了報告に理由と一緒に書く。
- データベースは使わない。サーバー側にモックのデータ層を作り、データはメモリ上に持つ（サーバーを再起動したら初期データに戻ってよい）。
- 画面からのデータの読み書きは、すべてサーバー側のAPIを通す。画面から直接モックのデータを読まない。
- 途中で私に質問せず、合理的に判断して進めてよい。
- 終わったら、最後に書いた形式で完了報告をする。

# 前提
- 利用者は従業員10〜30人程度の会社。PCのブラウザで使う。
- タイムゾーンは日本時間（Asia/Tokyo）。時刻は分単位で扱う。
- 画面の文言は日本語。

# 初期データ
- ユーザー5人（管理者1人、従業員4人）。氏名・メールアドレス・パスワード・役割を持つ。
- 従業員4人について、今月と先月の平日の勤怠データ（出勤・退勤・休憩）を入れておく。うち2件は「出勤だけ打刻して退勤がない日」にする。

# 受け入れ条件
1. ログイン：メールアドレスとパスワードでログインできる。ログインしていないと、ログイン画面以外は見られない。ログアウトできる。
2. 打刻：従業員は「出勤」「休憩開始」「休憩終了」「退勤」を打刻できる。今の状態で押せないボタンは押せない（出勤前の退勤、二重の出勤など）。サーバー側でも同じチェックをする。
3. 自分の勤怠一覧：従業員は月を選んで、自分の日ごとの出勤・退勤・休憩時間・実働時間・残業時間と、その月の合計を見られる。
4. 勤怠の計算ルール：実働時間 = 退勤 − 出勤 − 休憩時間。残業時間 = 実働時間 − 8時間（マイナスなら0）。退勤がない日は実働・残業を計算せず「打刻漏れ」と表示する。
5. 管理者の月次一覧：管理者は月を選んで、全従業員の出勤日数・実働時間の合計・残業時間の合計・打刻漏れの件数を一覧で見られる。
6. 管理者の修正：管理者は任意の従業員の任意の日の出勤・退勤・休憩を修正できる。退勤が出勤より前になる修正などは、サーバー側で弾いて画面にエラーを表示する。
7. CSV出力：管理者は月と従業員（全員も選べる）を指定して、勤怠をCSVでダウンロードできる。
   - 列：従業員ID, 氏名, 日付, 出勤, 退勤, 休憩(分), 実働(分), 残業(分), 備考
   - 日付は YYYY-MM-DD、時刻は HH:MM。打刻漏れの日は実働・残業を空欄にし、備考に「打刻漏れ」と入れる。
   - 文字コードは UTF-8（BOM付き）。Excelで開いて文字化けしないこと。
8. 権限：従業員は自分のデータしか読み書きできない。他人のデータや管理者用のAPIを呼んだら、APIが 403 を返す。ログインしていなければ 401 を返す。
9. 定期処理：毎日0時に、前日の打刻漏れを検出して記録する仕組みを用意する。管理者の画面で、検出した打刻漏れを確認できる。フレームワークの機能で書けない場合は、デプロイ先の機能を使う設定でもよい。その場合は理由を報告する。
10. テスト：勤怠の計算ルール（条件4）に単体テストを書き、テストが通る。
11. ビルド：型チェックとビルドが成功し、開発サーバーですべての画面が表示される。
12. README：起動方法、テストの実行方法、ログイン用のアカウント一覧を書く。

# 完了報告の形式
次の見出しで、この順に書く。
## 受け入れ条件
条件1〜12のそれぞれについて ○（満たした）／△（一部だけ）／✗（満たしていない）と、△と✗の理由。
## 追加したライブラリ
名前と、それを選んだ理由。
## 実行したコマンド
型チェック・テスト・ビルドのコマンドと、その結果。
## 判断したこと
指示に書いていなかったことで、自分で決めたこと。
## 残っている問題
分かっている不具合や、手を付けていないこと。
```
