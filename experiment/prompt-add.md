# 検証用の指示文（2段目：機能の追加）

1段目（[prompt.md](prompt.md)）で作ったアプリに、機能を足させるための指示文です。NuxtとNext.jsで、一字一句同じ文面を使います。フレームワーク名も入れません。

1段目のアプリをコピーした作業フォルダ（`nuxt-1-add` など）で新しいセッションを起動し、下のコードブロックの中身を**そのまま1回だけ**貼り付けます。

この段で見たいのは、「要るものを後から足すときの手間」「UIライブラリをどれだけ楽にカスタマイズできるか」「書き足す設定の量」です。そのため、指示文には特定のライブラリ名を書かず、「定番のもの」とだけ書いています。

```text
このフォルダには、小さな会社向けの勤怠管理Webアプリがあります（README を参照）。次の機能を追加してください。

# 進め方のルール
- TypeScriptで書く。
- 公式・定番のモジュールやライブラリは自由に使ってよい。追加したものは、完了報告に理由と一緒に書く。
- 今ある機能を壊さない。今あるテストは、すべて通る状態を保つ。
- 途中で私に質問せず、合理的に判断して進めてよい。
- 終わったら、最後に書いた形式で完了報告をする。

# 追加の受け入れ条件
A1. UI部品：定番のUIコンポーネントライブラリを導入し、ログイン、打刻、自分の勤怠一覧、管理者の月次一覧、管理者の修正の画面を、そのライブラリの部品（ボタン、フォーム、テーブル、モーダルなど）で作り直す。ライトモードとダークモードを切り替えられる。
A2. UIのカスタマイズ：UIライブラリのテーマ設定を使い、次の見た目を全画面に反映する。部品ごとにクラスやスタイルを書いて回るのではなく、ライブラリの設定で全体に効かせる。
   - 主色（ボタン、リンク、選択中の項目など）を、会社のブランドカラー #0F766E にする。ダークモードでも読みやすい明るさに調整する。
   - ボタンと入力欄の角の丸みを、全画面でそろえて小さくする（4px程度）。
   - 本文の書体を Noto Sans JP にする。
   - テーブルの行の高さを詰めて、1画面に多くの行を表示できるようにする。
A3. Lint：定番のLintの設定を導入し、Lintを実行するコマンドを package.json に用意する。そのコマンドでエラーが0件になる。
A4. 計測：Google Analytics（測定ID：G-XXXXXXXXXX）を読み込む。
   - 最初の画面の表示を妨げない方法で読み込む。
   - 利用者が画面上のバナーで同意するまでは、計測の送信をしない。同意したら送信を始める。
   - 打刻したときに、イベント「punch」を送る（種類：出勤・休憩開始・休憩終了・退勤）。
A5. 既存の動作：型チェック、テスト、ビルドが成功し、開発サーバーですべての画面が表示される。
A6. README：追加した機能と、Lintの実行方法を追記する。

# 完了報告の形式
次の見出しで、この順に書く。
## 受け入れ条件
条件A1〜A6のそれぞれについて ○（満たした）／△（一部だけ）／✗（満たしていない）と、△と✗の理由。
## 追加したライブラリ
名前と、それを選んだ理由。
## 変更したファイル
追加・変更したファイルの一覧と、それぞれ何のための変更か。設定ファイルや、全画面に効くつなぎ込み（レイアウト、プラグイン、プロバイダーなど）は分けて書く。
## 実行したコマンド
Lint・型チェック・テスト・ビルドのコマンドと、その結果。
## 判断したこと
指示に書いていなかったことで、自分で決めたこと。
## 残っている問題
分かっている不具合や、手を付けていないこと。
```
