# 04. 発表企画書

## タイトル案
- 「プラグイン全部入り。Nuxt で Web アプリをサクッと作る」
- 「テンプレート1つで爆速。Nuxt で Web アプリをサクッと作る」
- 「同じ指示を AI に出したら Nuxt と Next.js で何が違ったか」
- 「Nuxt はなぜ"気軽"なのか — エコシステムと AI で検証してみた」

## 一言でいうと
Nuxt は **Nuxt 4 で使えるモジュール 300 弱を、どれも 1 コマンドで足せる** ので、テンプレートから始めてSEO・計測・UI・サーバー処理まで揃った Web アプリをすぐ立ち上げられる。その「気軽さ」を、Next.js と同じ条件で AI に作らせて **数字で** 確かめる。

## 対象
Web アプリを作る機会のあるエンジニア(Vue/React 問わず)、技術選定に関わる人。

## 持ち帰ってほしいこと
1. Nuxt で「すぐ作れる」理由(モジュールの豊富さと入れ方の統一、規約・自動インポート)
2. SEO・スクリプト・サーバー処理を 1 コマンドで足す方法
3. AI 時代のフレームワーク選定で見るべき指標(トークン・介入回数・コード量)

## 検証結果によるストーリー分岐

| 結果 | 語り方 |
| --- | --- |
| Nuxt が全指標で有利 | 「規約とモジュールは AI にとってもショートカットだった」 |
| トークンは Nuxt 少、手戻りは Next 少 | 「AI は Next に慣れている。でも出来上がるコードは Nuxt の方が短く読みやすい」 |
| 差が小さく、2 回の間のぶれの方が大きい | 「フレームワークより AI の気まぐれの方が大きい。だから人が読み書きしやすい方を選ぶ」 |
| Next が全指標で有利 | 「AI 任せなら Next。でも人が書く・読む・テンプレート化するなら Nuxt の価値がある」+ MCP オン条件の追加検証へ |

## デモ計画(セクション4)
```bash
npm create nuxt@latest demo -- -t ui        # 1. テンプレートから立ち上げ
cd demo
npx nuxi module add @nuxtjs/seo             # 2. SEO 一式
npx nuxi module add scripts                 # 3. スクリプト管理
npm run dev                                 # 4. /sitemap.xml, /robots.txt を開いて見せる
```
※ 会場のネットワークに依存しないよう、事前に録画したバックアップを用意。
