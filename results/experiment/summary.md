# 検証結果：アプリを作る段ではNuxtの方が少ない手間で済み、機能を足す段ではテーマ設定の少なさ以外ほぼ互角だった

同じ指示文で勤怠管理アプリを作らせると、Nuxtは出力トークンが約2割少なく、コストは約3分の2、import の行は約4分の1でした。できたアプリに UI 部品・カスタマイズ・Lint・計測を足す段では、手間はほぼ同じで、同じ見た目を出すためのテーマ設定の行数だけが Nuxt で半分以下でした。どちらのフレームワークも、8回すべてで受け入れ条件をすべて満たしています。

## 要約

- **書く量（1段目）**：出力トークンは Nuxt 約7.5万、Next.js 約9.6万。import の行は 45 と 170 で、自動インポートの差がそのまま出た
- **読み回した量（1段目）**：入力とキャッシュのトークンは Nuxt が Next.js の約半分
- **選んだ道具（1段目）**：Nuxt は2回とも認証に `nuxt-auth-utils`、定期処理に Nitro Tasks を使った。Next.js は2回とも認証を自前で書き、定期処理も自前のタイマーで書いた
- **足す手間（2段目）**：出力トークンも時間もほぼ同じ。テーマ設定は Nuxt 17.5行、Next.js 42.5行
- **限界**：各2回、1つのモデルでの結果なので、傾向として読む

## 気づいたこと

**1段目では、Nuxt のモジュールと規約が AI にも使われていた。** Nuxt の2回はどちらも、ログインを `nuxt-auth-utils` に、毎日0時の処理を Nitro の `scheduledTasks` に任せていた。Next.js の2回は、セッションの署名やパスワードのハッシュ化、定期実行のタイマーを自分で書いている。Next.js 側のコード行数と import の行数が多いのは、この自前の部分と、明示的な import の両方による。

**2段目では、どちらも定番のライブラリで足せた。** Nuxt は2回とも Nuxt UI と `@nuxt/eslint`、Next.js は2回とも Mantine を選び、Lint は create-next-app に最初から入っている設定をそのまま使った。計測は、Nuxt が `@nuxt/scripts`（1回目）と `nuxt-gtag`（2回目）、Next.js が自前のコンポーネント（1回目）と公式の `@next/third-parties`（2回目）だった。

**差がはっきり出たのは、カスタマイズの書き方。** 主色・角の丸み・書体・表の行の高さを全画面に効かせるために、Nuxt UI は CSS の変数と `app.config.ts` の十数行で済んだ。Mantine は `createTheme` に主色の10段階や部品ごとの既定値を書き、40行あまりになった。部品ごとの上書きは、Nuxt が0か所、Next.js が1回目だけ1か所だった。

**エラーの回数には差がない。** ビルドと型チェックの失敗は、Nuxt が計3回、Next.js が計2回で、どれも AI が自分で直した。人の介入は8回とも0回だった。

## 発表でどう語るか

`docs/context/04_presentation-proposal.md` のストーリー分岐では、「規約とモジュールは AI にとってもショートカットだった」に近い。ただし2段目はほぼ互角なので、次の言い方が数字に合う。

> AIに作らせても、Nuxt は規約とモジュールのおかげで書く量が少なかった。後から足す手間は Next.js とほぼ同じで、違いが出たのはカスタマイズの設定の少なさだった。

## 数字を読むときの注意

- **追加した依存の数**：Nuxt の6件には `typescript`、`vue-tsc`、`@types/node` が含まれる。Nuxt の最小テンプレートはこれらを入れないが、create-next-app は最初から入れるため、数が多く見える。機能のために足したものは、Nuxt が `nuxt-auth-utils`・`zod`・`vitest`、Next.js が `vitest`（2回目は `server-only` も）。
- **テーマ設定の行数**：数え方（どの行を「テーマ設定」とみなすか）は判定する人の判断が入る。数えた行は各回の JSON の notes に残してある。
- **next-2 の完了報告**：指示した形式の完了報告がなく、Claude Desktop の「次のステップ」の枠で作業を終えていた。受け入れ条件は自分で動かして判定しているので、結果には影響しない。
- **実行のしかた**：各回とも Nuxt と Next.js を同時に動かした（交互ではない）。Next.js の回の指示文は1行目が「Next.js」で、「（App Router）」が抜けていたが、4回とも App Router で作られている。
- **固定できない条件**：学習データの量（Next.js の方が多い）は揃えられない。Claude Desktop 組み込みのブラウザとユーザー設定のスキルは、両方のセッションで使える状態だった。
- **統計的な結論ではない**：各フレームワーク2回、1つのモデル（claude-opus-5-5、effort high）での結果。モデルが変われば結果も変わり得る。
